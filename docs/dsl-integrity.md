# 顺序 DSL 生成与完整性

当前执行器使用应用、流程和顺序步骤。读取从当前应用流程列表开始，遇到服务端声明的流程引用时按来源流程编码读取定义。步骤接口仍使用明确的 flowCode，公共模板与流程图字段不会参与解析。

主流程使用 steps，普通子步骤使用 children，代码块使用 body，被调用流程集中在 subflows。应用参数和执行元数据按顺序构建器规范化；保留 NEXT、条件跳转、重试、超时和禁用状态，这些属于顺序执行语义。

普通调用在当前应用内按名称唯一解析。引用流程保留调用处的流程名称和编码，步骤接口返回空列表时沿已声明的引用读取来源步骤。引用流程的后续调用优先在来源应用中解析，再查当前应用。本地可编辑流程的草稿和候选在发现后续依赖前覆盖。调用依赖递归加载、去重，缺失目标、空步骤、引用循环或同名冲突会给出错误。只读查看可展示已有内容并单独报告加载异常。

打开编辑页采用草稿构建，可打开空代码块进行修复。保存及 DSL 调试执行严格校验步骤、参数、代码块、跳转和完整调用闭包，技术成功不代表业务办结。

测试覆盖引用来源的递归读取、来源优先级、引用流程只读、顺序条件跳转、子流程草稿与候选隔离、代码块补齐后保存，以及原生界面中的完整 JSON 查看。
