# DSL 生成与完整性检查

执行链路为：原生步骤 → 参数及结构规范化 → 应用/引用/模板流程解析 → 应用本地子流程草稿或本次候选 → 递归扫描依赖 → 完整执行包校验 → 执行请求。

## 原生步骤转换

- 参数以原始 actionArgs/targetArgs JSON 为底，再叠加参数明细中明确提供的值。部分 VOS 或缺少 fieldValue 不再删除原始参数；0、false、空字符串、嵌套 JSON 保留。明确隐藏的参数清空，字符串隐藏标志 0 不视为 true。
- 同时支持平台返回的扁平 level=0/1 和已经嵌套的 list，保持原始顺序。孤立子步骤、超过两级或同一父节点混用嵌套与扁平子项时拒绝转换，不再清空子步骤或自动提升到主级。
- 平台原生步骤缺失或复用 stepCode 时，读取边界为每次出现分配稳定的唯一标识，保留步骤顺序、参数、数据库行身份和原编码记录，代码块子项的 groupCode 同步。重复数据库行身份不复制到新标识的行。打开和调试不写服务器，只有用户保存时才提交修复后的编码；内部修复标记不进入保存正文。模型编写的 DSL 仍严格拒绝重复编码，名称和跳转冲突也不会绕过检查。
- 保留执行策略、应用参数及申报/模板元数据。普通 children 属于主执行列表，codeBlock.body 属于代码块执行列表；NEXT 是执行器支持的跳转哨兵，不清理为非法目标。
- 禁用步骤不要求执行参数完整；禁用普通父步骤的 children 仍按活动步骤检查，禁用代码块的 body 不要求执行参数完整。结构及参数键仍校验。

## 子流程装配

1. 优先按调用上下文的来源应用查找，再回退当前应用，最后查公共子流程模板。公共模板使用现有 robot/flow/listTemplate 接口，templateType=1、flowType=2。
2. relationFlowCode 和 templateFlowCode 可逐级追溯。模板实例读取步骤时传 templateFlowCode，让平台返回合并过实例参数的步骤；不能仅取模板裸步骤代替实例。实例步骤为空时继续追溯来源；无显式引用的空子流程可按执行器行为回退同名公共模板。
3. 保留调用侧 flowCode/flowName，来源流程用于获取实际步骤及继续解析依赖。公共模板允许 appCode 为空，不把它误判为不存在。
4. 本地可编辑子流程草稿和本次子流程候选在依赖扫描前覆盖，再规范化参数。候选新增的下级调用也进入闭包。run_current_dsl 不混入未应用的子流程候选；run_proposed_dsl 和续跑按各自语义显式传入候选。
5. active subFlow/finalFlow、普通子步骤及启用代码块内的调用均递归加载。重复依赖仅装配一次，引用链循环报错。同一名称解析到不同编码时拒绝打包：执行器按全局名称查子流程，不能安全表达两个同名来源。

## 提交前检查

完整包必须包含每个活动静态调用的目标、非空步骤和唯一流程身份。检查步骤标识、参数对象、代码块层级、执行列表内的跳转与总步骤数（5000）。缺少配置时保留错误并给出调用路径及已搜索的应用/模板范围；不跳过缺失流程，不虚构步骤，也不向执行器提交不完整包。

## 验证

tests/debug-dsl.test.js 覆盖参数合并、层级保留、执行元数据、模板回退、实例引用、跨应用、草稿依赖闭包、同名冲突和非法结构。tests/step-details.test.js 覆盖条件参数与禁用步骤语义。

tests/electron-smoke.js 使用本机模拟平台及执行器，检查模板实例查询参数、公共模板递归、嵌套调用、候选新增依赖和当前/候选运行分离。没有连接真实申报网站或执行真实业务。
