# 顺序 DSL 生成与完整性

当前执行器只使用应用、流程和顺序步骤。读取只请求当前应用流程列表及明确 flowCode 的步骤接口，步骤请求不携带模板或流程图参数。不查询公共模板、不追踪旧引用、不跨应用回退。历史接口返回的旧字段会被过滤。

主流程使用 steps，普通子步骤使用 children，代码块使用 body，被调用流程集中在 subflows。应用参数和执行元数据按顺序构建器规范化；保留 NEXT、条件跳转、重试、超时和禁用状态，这些属于顺序执行语义。

子流程在当前应用内按名称唯一解析，依照其编码读取实际步骤。本地草稿和候选在发现后续依赖前覆盖；调用依赖递归加载、去重。缺失目标、空步骤或同名不唯一会给出具体错误，不用其他来源填补。只读查看可展示已有内容并单独报告加载异常。

打开编辑页采用草稿构建，可打开空代码块进行修复。保存及 DSL 调试执行严格校验步骤、参数、代码块、跳转和完整调用闭包，技术成功不代表业务办结。

测试验证：旧字段不影响来源选择、不会调用旧接口、空子流程不会回退、顺序条件跳转保留、子流程草稿与候选隔离、当前应用权限绑定、代码块补齐后保存，以及原生界面中的完整 JSON 查看。
