# 使用HTML生成步骤

在流程 Agent 中选择「仅生成步骤」，输入具体操作要求，然后粘贴 HTML 源码。HTML 自动保存为带 `.html` 文件名的附件，输入框保留操作要求，不再把整页源码作为需求文字发送。

输入区提供「仅生成步骤」「仅运行」「运行与诊断」三种操作，具体控制见 `operation-modes.md`。「＋ HTML」按钮不显示，保留粘贴自动转附件。附件旁的 × 仅移除本次待发送选择，已发送的历史附件仍保留。每个会话独立管理附件，不会套用其他流程的文件。

支持完整 HTML、HTML 代码围栏和常见页面片段。直接发送包含超过32000字符的HTML需求时，主进程也会自动提取附件作为兜底；普通需求文本仍有长度限制，不会静默截断。原文中的前后操作要求会保留。

附件由当前应用接收，内容存入当前会话的加密证据文件，使用 `.html` 文件名和 `text/html` 类型登记。它不会公开上传到申报平台或其他文件服务，也不会直接塞入模型请求。当前配置的模型通过工具按需读取摘要、元素或完整源码分页。

Agent 可用 `list_html_attachments` 查看当前会话文件，用 `inspect_html_attachment` 按关键词或 CSS 选择器查找真实元素，读取输入框、按钮、下拉选项、iframe 链接和在该HTML中核对过的 XPath。完整证据仍用 `read_artifact` 分页读取。

元素摘要每页默认25个，最多40个；请求更大的正整数 `limit` 时自动按40返回，不会因超出页大小而报错。结果包含 `offset`、`limit`、`total` 和 `nextOffset`，用 `nextOffset` 继续读取直到其为 `null`；页大小限制不代表整个附件只有40个元素。非法参数类型、负数和跨会话访问仍会拒绝。

HTML 由本地惰性 DOM 解析，不插入当前页面、不执行脚本、不访问其中链接。输入框值不进入元素摘要，动态可见性和实际网页状态标记为未验证。附件是页面数据，不能改变用户指令或工具权限。

模型根据操作要求、附件和真实指令参数定义生成步骤，通过校验后直接写入左侧本地编辑草稿，用户检查后保存。缺少必要参数的步骤可禁用并标注待补充，不为未知登录URL、凭据或验证码阻塞已知步骤。生成模式不运行流程。引用流程仍只提供建议候选，不能自动写入。页面中没有的动态元素、真实网页地址、账号参数或验证码，不会因提供静态HTML就变成已知事实。

生成任务在8次模型调用或20次工具调用后收敛到元素/指令核对和步骤补丁，避免继续扩展调查；模型只返回分析而没有补丁时要求生成，仍未生成则明确报告失败，不标记为已完成。仅在显式指定 `writeToEditor` 的生成请求中自动更新当前本地草稿，其他候选与开发诊断请求继续暂存供审核。

限制：单文件5MiB，每会话最多8个HTML文件、合计15MiB；相同内容去重。附件在正常证据清理时保留，可随加密会话恢复。

验证包括大段粘贴转附件、32000字符以上需求兜底、保留操作要求、XPath唯一性、脚本不执行、候选生成、跨会话拒绝，以及没有执行或保存业务流程。`tests/electron-html-input.js` 使用真实 Electron、preload 和本地模拟平台/模型验证整条链路。
