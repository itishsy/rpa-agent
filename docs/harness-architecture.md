# Harness 控制设计

## 设计依据

本次以工作区内 `codex` 源码为主要依据，阅读了 Turn 循环、输入队列、工具并发、授权编排、取消和历史归一化。源码版本、具体位置与改动映射见 [Codex 源码阅读与优化记录](codex-source-review.md)。RPA 的副作用控制、执行租约和未知结果核对是本项目的适配，不是对 Codex 的逐项复制。

没有复用旧 IDE 的 Harness、案例状态机、`aiAgentSession` 或模型提示词。

## 模块

```text
原生 Renderer / MCP 客户端
          │ 用户输入、允许、停止、只读查询
          ▼
主进程 IPC 来源校验与平台身份绑定
          │
          ▼
Harness.start(Session, Turn)
  ├─ Context：系统规则 + 当前状态 + 历史完整轮次
  ├─ Model：只返回 assistant message / tool calls
  ├─ Registry：schema 校验 + read/edit/execute 效果分类
  ├─ Policy：模式、预算、一次性授权、版本/作用域绑定
  ├─ ExecutorLeases：同一执行器全局互斥
  └─ Store：先写加密检查点，再发布有序事件
          │
          ▼
平台设计服务 / Java 调试执行器 / 只读经验库
```

## Session、Turn 与 Item

Session 作用域由平台 ID、平台 URL、账号、执行器地址、应用与流程组成。历史记录不可跨作用域打开。平台/执行器设置在运行或等待授权期间不可修改。

Turn 是一次用户请求，持有独立 AbortController、工具计数、执行计数和时间预算。同一 Session 不能同时存在两个 Turn。Item 是工具调用；状态和事件归主进程所有，Renderer 只是视图。

状态包括 `idle`、`running`、`waiting_approval`、`stopping`、`completed`、`failed`、`cancelled`、`budget_exhausted` 和 `interrupted`。这些表示控制循环状态，不表示业务申报成功。检查点中的 `turn.calls` 记录每个调用的身份、效果、状态与执行阶段；事件包含 turnId/callId。

每次模型响应先整体校验，再调度工具并回送结果。只有明确标记 `parallelSafe` 的相邻只读工具可并发，最多4个；更新草稿、指令定义缓存和真实执行形成串行屏障。结果按模型调用顺序写入，事件可按真实完成顺序到达。重复 callId 在执行前拒绝。默认预算为24次模型调用、80次工具调用、1次获准执行、15分钟与90000字符模型输入（包含工具定义）。构造 Harness 时可以修改。

“运行中补充”通过 expectedTurnId 进入持久化输入队列，不启动第二个 Turn，不改变原模式，也不授予执行权限。排队输入优先于旧采样和尚未派发的工具；待授权调用立即撤销。当前动作已经开始时，补充指令不会代替停止按钮，等该动作结束后继续推理。

## 工具权限

| 效果 | 示例 | 控制 |
| --- | --- | --- |
| read | 当前 DSL、指令定义、参考流程、执行 DOM、证据分页 | schema 校验、作用域检查、只读结果 |
| edit | 更新计划、提出候选 | 仅修改本地草稿；候选必须匹配基线与 revision |
| execute | 当前/候选/单步运行、失败续跑 | 执行预算、预检与依赖复核、执行器租约；工作台及已连接MCP无需权限确认 |

Agent 和 MCP 均没有直接应用候选、保存步骤、修改断言、发布或操作 UKey 的工具。用户在 Renderer 的显式操作才进入这些业务入口。生成模式从 schema 中移除执行工具，并在实际 dispatch 再次拒绝伪造执行调用。

模型不能通过工具参数指定任意执行器地址、任意平台凭据或其他应用作用域。真实调用使用主进程保存的 Session scope。

## 授权、取消和未知状态

执行工具先完成账户、DSL、指令及子流程预检，生成不可变 `executionRequest`。按用户设置，工作台模型轮次、手动执行和已连接MCP均传入 `executionConsent:true`，不发出权限确认请求。执行前仍重新构建并比较执行请求，提交时再同步检查本机工作区依赖；参数、scope、revision、DSL、候选、断言、实际账户或完整执行包发生变化时，拒绝过期执行。实际提交使用已复核的不可变执行包。Harness保留可选审批能力供独立嵌入使用，当前工作台入口不使用审批等待。

本机依赖快照保守覆盖同平台、账户、执行器及应用的已打开工作区，包括 revision、DSL、基线和只读/服务器变化状态。远端步骤通过授权后的重新读取复核；平台缺少条件版本接口，无法检测最后一次读取之后其他客户端的修改。主进程仍只提交已获准的包，不把后来内容混入执行。

停止会中断模型等待、取消待处理授权。RPA 工具把异步预检和实际执行提交分开：预检期间停止不会启动或取消尚不存在的任务。提交前持久化执行阶段；只有真正发出调试请求后才按有效 taskCode 发送 cancel。执行租约持续到调试请求与 cancel 请求均结束。只读取消可快速返回；有副作用的工具必须完成清理，不能通过 Promise.race 提前释放占用。延迟返回的候选也会在写入前检查取消与补充输入。

调用阶段依次为 `preflight → prepared → submitted → result_received → result_persisted → finalized`。收到执行器结果后，先将结果摘要、调用身份、预分配证据编号和 UNKNOWN 核验状态写入检查点，再写证据，最后异步核验。结果记录分别保存 `rootDslFingerprint`、`bundleFingerprint`，兼容字段 `fingerprint` 指向完整包指纹。证据失败保留已知结果并明确标记 `evidenceState=failed`；核验异常保留执行状态，仅将业务核验记为 UNKNOWN。结果保存失败终止本轮，不交给模型自动重试执行。

启动时扫描未完成检查点，将没有终结的轮次改为 `interrupted`。已知结果从调用的 `resultRecord` 恢复执行摘要和缺失工具输出，证据缺失及未完成核验保持 UNKNOWN，不重放执行。已提交但未收到结果的调用恢复占用保护；兼容旧版 `executing`，旧版 `observed` 缺少结果记录时也保守隔离。普通读取和未提交的预检不会锁住执行器。解除占用必须通过界面核对同一执行器的明确“已停止”状态；远程连接失败、状态未知或 HTTP 请求未结束均不足以解除。localhost、127.0.0.1 和 ::1 按同一本机地址占用。

租约协调本主进程中的会话，不能替代执行器服务端对来自其他客户端的并发限制。不会自动重放 execute。续跑仍须有明确失败、resumable、executionCode，并保持原账户。

## 候选、保存与核验

DSL 的参数合并、模板实例、跨应用引用和调用闭包规则见 [DSL 生成与完整性检查](dsl-integrity.md)。执行包在发出请求前校验，缺失调用目标不会被静默跳过。

候选保留基线指纹和 revision。指令必须存在，参数键必须来自真实指令定义，步骤编码唯一，不允许脱敏占位符进入可执行配置。原生序列化不依赖 Vue 的字段组件。

条件参数按控制项的当前选项逐层展开，仅启用当前分支可达的后续控制项。隐藏控制项中的旧值不能重新启用其他分支；例如 H5 的扫码/人脸扫码不校验短信分支的 inputType、smsXpath、inputXpath。编辑器显隐、保存和执行预检共享同一规则。执行前用校验后的原生参数行重新构造 DSL，再装配完整执行包，隐藏字段清空但不修改编辑器草稿；短信分支真正需要的参数仍严格校验。

子流程修复必须先展开主流程实际调用图，再确认目标属于同应用且没有引用关系。候选同时绑定主流程版本、子流程版本及两份基线，运行时将子流程候选装入主流程调试包。用户应用后切换至目标工作区，再单独保存子流程；不会把子流程步骤插进主流程。生成模式不能借此修改别的流程。

应用候选只改变编辑器草稿。保存前再读取服务器步骤检查基线；恢复会话与服务器不同则拒绝直接保存。保存配置不意味着业务成功。服务器缺少条件版本写接口，前置读取无法完全消除跨客户端竞态。

执行结果绑定本次 DSL 指纹、revision、账户和独立证据编号。业务核验只检查新鲜、完整且可唯一确定的 FINAL 页面。缺少正向断言或证据时为 UNKNOWN；失败保留 FAILED。修改断言会令旧核验失效。单步执行不升级为完整业务 VERIFIED。

## 上下文与存储

调查预算预留最后一次模型请求作文本收尾，默认最多23次调查请求加1次结论请求，总上限仍为24次。结论阶段禁用工具，按已有证据说明问题、具体修改建议、推测及验证缺口，先持久化并显示建议，再发出 budget_exhausted。工具/上下文预算到限也进入收尾；模型失败、上下文装不下或时间耗尽时提供标明证据缺口的本地排查建议。用户主动停止不再发起收尾请求，也不接纳迟到结论。

get_subflow_context 和 get_app_flow_steps 可只读检查当前调用闭包内的引用/跨应用子流程；返回 readOnly/advisoryOnly 标识。读取不授予编辑权限，propose_dsl_patch 仍通过独立的可编辑子流程校验；闭包外任意流程不可借此读取。不可编辑应转为建议和来源流程定位，不作为配置错误，也不要求反复调用失败工具。

上下文构建不再删除原始对话。先在副本中按 assistant 调用批次配对结果，补缺失输出、去孤立输出，再生成有限长度的模型输入。摘要、计划与工具观察使用 user 上下文数据承载，不提升为 system 指令。保留当前用户目标及完整最新调用批次；不可拆分批次仍超预算时保存进度并停止。旧版已经删除的历史无法凭空恢复。这是确定性投影，不是 Responses API 的加密 compaction；原始对话可通过 read_history 分页读取。

长工具观察返回短预览及 artifactId；`read_artifact` 和 `inspect_page_dom` 分页读取完整现场。执行证据单独加密，检查点只保留最近五次执行摘要与索引。每个会话最多索引 60 个证据对象，事件最多保留 1000 条；历史会话当前不自动按日期删除。

证据分页默认请求10000字符，实际单页最多14000字符；超大 length 在读取时自动限制，不因超过页长而反复 schema 报错。分页还按 JSON 序列化后的15000字符预算缩短，避免转义后的内容再次包装成 artifact。结果返回 length、requestedLength、maxLength 与 nextOffset；后续读取必须使用实际 nextOffset，null 表示结束。负数、非整数及其他类型的参数仍拒绝。

持久化在事件广播之前完成，事件带单调递增 sequence，客户端可通过 `agent:events` 按游标补读。审批也先入检查点再发给界面。主进程重启不会将“曾广播”误认为“已执行”。

界面事件发送失败不会改变已提交操作的结果。工具事件带独立调用身份，避免并行时串号；Renderer 只接受最新快照，避免异步回读将已撤销授权重新显示。

每个工具支持可选 _purpose 展示参数，模型应说明本次调用与用户任务的关系；主进程将其脱敏后写入调用记录和 item/started 事件，界面在工具名下显示“目的”。旧模型和直接调用缺少该字段时使用工具描述兜底。_purpose 最多300字符，参数校验后剥离，不传给业务执行器，也不参与执行授权。

模型适配层返回消息及独立的 finishReason、completionStatus、usage。只有正常完成的响应可进入工具调度；长度截断、过滤、拒绝、未知结束原因和不完整结束状态保存终止原因并失败结束，不执行该响应内的工具，也不发布 turn/completed。缺少 finish_reason 的兼容服务标记 legacy，仍执行原有消息结构校验。元数据不会写入下一次 API 请求的 assistant 消息。当前不自动续接截断文本，用户可在已有历史上继续。

## Electron 与 MCP 边界

Renderer 禁用 NodeIntegration、启用 ContextIsolation 与 WebSecurity，使用固定 preload 通道白名单。IPC 同时校验本机窗口、主 frame 与文件 URL；拦截页面导航、弹窗与 webview。业务网络请求从主进程发出，拒绝平台路径越界和重定向，不把密钥传给页面。

MCP 仅监听 `127.0.0.1`，使用随机 Bearer Token，并绑定当前 Session。MCP 的执行请求仍经过同一 Harness 授权、预算与租约，不存在另一套绕过 Renderer 的执行循环。

切换到其他工作区时关闭原 MCP 绑定。客户端断连会撤销等待中的授权，并中断对应轮次，防止在授权界面已经不可见时继续执行。
