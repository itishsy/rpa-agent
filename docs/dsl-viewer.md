# DSL 查看结构

字段层级沿用 IDE 的顺序步骤结构，读取行为按当前执行器约束：只读取当前应用的实体流程与步骤，不读取流程模板、流程图或旧跨应用引用。

- 主流程：`appCode`、`appName`、`flowCode`、`flowName`、`steps`，以及非空的应用参数和执行元数据。
- 步骤：`stepCode`、`stepName`、`actionCode`，参数为对象；默认执行选项和空字段按构建规则省略。
- 普通子步骤在 `children`，代码块步骤在 `body`。
- 被调用流程集中在顶层 `subflows`，每项包含 `flowCode`、`flowName`、`steps`；多级调用递归加载、去重。

查看入口先读取当前本地草稿及其依赖，再用 `services/dsl-document.js` 经共享构建器生成文档。编辑器元数据和读取诊断不进入 DSL JSON；诊断独立展示在“加载提示”，复制 JSON 仅复制 DSL。查看器默认展开三层。

查看保留禁用分支和未保存子流程草稿，加载失败会提示，且不会触发保存或执行。`tests/dsl-document.test.js` 以相同原生步骤调用本地 IDE 源码和 Agent 构建器，对主流程、参数、普通子步骤、代码块和递归子流程结果进行完整比较。

子流程仅按当前应用流程列表中的名称解析编码，读取该编码对应的步骤。缺失或为空会明确报错，不回退任何模板、旧引用或其他应用。旧字段从读取结果和 DSL 文档中剔除。

查看器顶部的“定位流程”列出主流程与所有已加载子流程，并统计包含普通子步骤、代码块在内的总步骤数。选择子流程时折叠主流程的长步骤列表，展开并滚动到对应子流程；JSON 源码和复制仍保留完整文档。加载提示默认展开。

打开编辑页、读取子流程上下文及比较服务器保存基线时使用草稿构建，空代码块可以先打开、补充步骤。保存和 DSL 调试执行仍进行严格校验。编辑页只读取当前流程编码的步骤，空步骤不会触发其他来源查询。
