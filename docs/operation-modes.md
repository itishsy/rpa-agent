# 流程操作模式

| 下拉选项 | Harness 控制 | 步骤修改 | 执行方式 |
| --- | --- | --- | --- |
| 仅生成步骤 (`generate`) | 模型仅可读取与编辑；执行工具即使被伪造调用也会拒绝 | 通过验证后生成待审核补丁，确认应用后进入左侧草稿，待用户保存；无编辑权限的流程仅暂存建议 | 不执行 |
| 仅运行 (`run`) | `runOnly` 确定执行入口；不启动模型轮次，不提供模型工具 | 不生成或应用补丁，须先保存已有修改 | 校验账户及服务器基线后运行已保存流程，沿用执行器占用、超时和不确定结果隔离 |
| 运行与诊断 (`develop`) | 模型可读取、编辑及通过受控执行工具采集现场；每轮执行预算、租约、取消与证据记录继续生效 | 补丁作为候选审核，不自动写入左侧或保存 | 按用户目标运行、诊断；不重放结果未知的执行 |

`agent/mode-policy.js` 定义各模式允许的工具效果；工具列表与 Harness 调度均使用该策略。模式在启动轮次时绑定，运行中更改下拉框不会改变当前轮次权限。`writeToEditor` 仅在生成模式生效。

常规运行入口 `workspace:run` 与 `agent:start(mode:run)` 共用服务器流程执行函数，并交由 Harness 管理运行互斥及操作状态。仅运行期间禁止修改步骤、账户或启动同会话模型轮次；网络中断后保留未知执行结果，核对执行器后才能再次运行。

模式切换保留需求草稿和附件。仅运行时需求输入框禁用，发送按钮显示「运行」，执行时不将草稿或附件送给模型。Agent 接管默认选择运行与诊断。
