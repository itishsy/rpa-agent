# rpa-agent

原生 Electron RPA 工作台。项目名称为 `rpa-agent`，主进程使用 CommonJS，界面使用 HTML、CSS、JavaScript，不依赖 Vue、React、Vite、Webpack 或 Web 开发服务器。源码与运行依赖均位于本目录，不加载 `rpa-ide/dist`，不需要旧项目才能运行。

## 启动与打包

```powershell
cd D:\Sourcecode\git\rpa\rpa-robot\rpa-agent
npm ci
npm start
```

当前工作区已利用本机现有 npm 安装准备好独立 `node_modules` 和裁剪后的依赖锁，可直接 `npm start`。离线依赖准备工具是 `node tools/bootstrap-local.js <已有安装目录>`；它仅在准备阶段复制本项目依赖，不构成运行时依赖。

```powershell
npm test
npm run check
npm run test:electron
npm run test:business
npm run test:shell
npm run test:design
npm run test:auth
npm run pack
npm run dist
```

受限环境中可使用已经安装的 Electron 生成未签名目录包：

```powershell
node node_modules/electron-builder/cli.js --dir --config.electronDist=node_modules/electron/dist --config.win.signAndEditExecutable=false
node tools/verify-package.js
```

目录包位于 `release/win-unpacked/rpa-agent.exe`。NSIS 安装包与签名未作为本次验证通过项。

本次独立用户登录版本输出到 `release/user-login/win-unpacked/rpa-agent.exe`（原目录被运行中的程序占用）。对应校验命令为 `node tools/verify-package.js release/user-login/win-unpacked`。

最新流程窗体优化版本输出到 `release/flow-window/win-unpacked/rpa-agent.exe`，校验命令为 `node tools/verify-package.js release/flow-window/win-unpacked`。

## 使用

1. 启动后先使用 RPA IDE 的工作台用户账号登录。登录、菜单和应用列表接口与 IDE 一致，主页按登录用户 Token 获取有权访问的应用，与系统设置中的执行器平台账号无关，无需添加或连接平台即可查看应用。默认 API 地址与 `rpa-ide/public/index.html` 一致，其他部署可在登录页的“登录服务设置”填写 API 根地址。用户密码与 Token 仅保存在内存，重启需重新登录；只记住服务地址和用户名。
2. 主界面左侧有“主页 / 任务监控 / 执行器管理 / 工具 / 系统设置”五个图标入口。主页字段为应用名称、版本状态、版本号、最新发布时间，操作列只有“流程设计”。“系统设置 → 平台管理”配置执行器连接业务平台所用的账号，左侧“执行器管理”独立管理本机令牌、远程连接及其状态，支持添加、移除、保存、只读刷新、本机启停、平台切换和日志；这些设置不改变工作台用户身份或首页数据。“AI 模型”配置兼容工具调用的模型。“外观”提供深浅/跟随系统、强调色和密度。退出或登录过期后返回登录页，清除当前页面数据，关闭应用流程窗口；运行中的轮次需先停止再退出；登录过期时 Harness 会主动请求停止。工具页按需求预留。
3. 主页支持分页、名称和状态筛选、添加应用及当前页导出。点击“流程设计”打开无菜单的原生应用窗口，默认筛选主流程。类型使用复选框，服务项目/申报系统使用可搜索多选下拉，长列表在窗口内滚动。行操作仅有“设置步骤”和“编辑”；在编辑弹框修改执行顺序并保存，删除需展开删除区勾选确认。复制、关联、状态和历史保留在编辑框的其他操作中。排序服务失败会明确提示已保存的流程信息和未完成排序，允许重试。
4. 流程行点击“设置步骤”，默认展示步骤列表与展开的 Agent 两栏；属性通过步骤旁的设置按钮弹出。顶部先选执行器，再选择该执行器的申报账户，切换执行器会建立独立会话、重新读取账户，旧账户/执行记录不带入新会话。支持两级步骤、代码块、复制粘贴、排序、禁用、跳转、重试、等待、超时、完整 DSL 和流程图。属性输入需点击“更新步骤”后再保存。“导入录制”先预览录制步骤，“采集参数”等待采集工具复制结果，“图片参数”支持100KiB以内的PNG/JPEG。
4. 选择调试账户。可运行当前流程、候选或单个步骤；最近失败记录有 `resumable` 标记时可续跑。真实运行会操作业务网站。
5. 向 Agent 描述需求。候选先审阅，再点击“应用候选”和“保存配置”。主流程及其实际调用的同应用可编辑子流程分别校验版本；子流程候选应用后进入目标工作区保存。仅生成模式不能执行。模型提出执行请求时，需要在当前工作台明确允许该次调用；用户直接点击运行按钮即授权该次运行。
6. 在“业务断言”配置业务预期。只有完整且唯一的新鲜 FINAL 页面可用于核验；技术成功、单步成功或没有断言均不能证明业务成功。
7. “会话归档”恢复历史对话、计划、候选和证据。进程中断后不自动重放真实执行；浏览器现场由执行器持有，不能随会话文件恢复。
8. “高级业务工具”提供模板、执行计划、参数、账户及记录的接口表单。查询参数与 JSON 正文分开配置，写操作先展示完整请求供用户提交；应用和流程的常用操作在独立业务页面完成。
9. “读取全部应用经验”分页读取当前账号可见应用与流程，以最多 4 个请求并发展开引用。支持停止、JSON/GZIP 导入导出与 Agent 检索；目录均为 `UNVERIFIED_REFERENCE`。

## Harness

没有移植 `rpa-ide/harness` 或旧 `aiAgentSession`。控制循环、工具策略、上下文裁剪、审批、执行租约、会话和证据存储均为新实现。设计参考 [OpenAI 的 Codex 平台说明](https://developers.openai.com/blog/codex-as-a-platform) 与 [Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)，在 RPA 场景实现相应的会话、轮次、工具和事件边界；并非接入或嵌入 Codex App Server。

本次又根据工作区本地 Codex 源码进行控制逻辑优化，新增运行中补充、受限只读并行、执行提交前复核、非破坏性历史投影及未知执行恢复保护。阅读的源码版本、位置和修复映射见 [Codex 源码阅读记录](docs/codex-source-review.md)。

详细说明见 [Harness 架构](docs/harness-architecture.md)、[业务服务来源](docs/service-provenance.md)。

运行中使用“运行中补充”调整需求；要中断已经开始的网站动作仍须使用“停止”。页面刷新会重连活动轮次并恢复待授权卡片。进程中断或网络异常造成执行结果未知时，请先停止对应执行器，再点击“核对并解除占用”；远程连接失败不能作为停止证据。

## 数据与限制

- 数据保存在 `%APPDATA%/rpa-agent-electron`，避免与旧 IDE 已使用的 `rpa-agent` 数据目录冲突。不会复制旧账号、令牌或生产数据。
- 密码、密钥、会话与证据由 Electron `safeStorage` 加密；加密不可用时拒绝持久化，不退回明文。
- DOM、ctx 与截图等完整证据独立加密保存，会话只存摘要及证据索引，避免每次事件重写整份现场。工具输出较长时通过 `read_artifact` 分页读取。
- 文本脱敏不能证明自然语言个人信息全部清除；截图仅进入本机加密证据，不进入经验导出。不要把经验目录当作已核实的业务规则。
- 保存前检查服务器步骤基线，但旧设计服务没有原子 compare-and-swap 接口；最终并发写入保护仍需服务器提供版本条件。
- 模型 API 当前为完整响应；界面提供轮次/消息/工具/授权事件，不实现逐 token 流式显示。恢复的是会话记录，不是执行器的浏览器进程。
- 本次没有访问真实平台、模型或申报网站，不能将离线回归视为真实业务验收。
